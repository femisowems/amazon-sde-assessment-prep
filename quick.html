Amazon SDE Online Assessment — Quick Reference

Everything that matters for the sitting itself, on one page: workflows, prompts, quick hints, and JavaScript solution templates. General preparation material — no leaked questions. Practice prompts are for before the test; Q1 is unaided during the test, and the Q2 prompts are for the built-in assistant only.

At a glance

Q1 · ~40 min
One traditional problem. 2 sample + 13 hidden tests. Medium to Medium-Hard. No AI.
Q2 · ~60 min
Repo task in a full IDE. Framework locks before you start — pick your daily stack (Node.js for JS candidates).
Work Simulation
Rate actions for effectiveness. Leadership Principles decide it. May run longer than its label — don't rush.
Work Style Surveys ×2
Forced choice, no neutral. First instinct, consistent answers.

Order matters: finish Coding (Q1) first — once you move to the repo section, you cannot go back. One sitting, single monitor, latest Chrome/Edge.

Go / No-Go — all five, or wait

  • ☐ Demo done for both formats; Run Tests, AI panel, and Submit located
  • ☐ Two timed Mediums: one fully passing in 40 min, the other at least a working partial
  • ☐ Repo drill: 3+ bugs fixed from failing tests in 45–60 min
  • ☐ Templates below typable from memory, including (a,b) => a-b
  • ☐ Rested, quiet single-monitor block secured for the full sitting

All five → GO. Any missing → WAIT and use the extra days — there is no reported bonus for submitting early in the window.

Q1 — Quick hints

The 40 minutes

TimeDo
0–5Restate inputs/output/constraints in plain words. Name the brute force and the complexity the constraints demand.
5–10Pick the pattern. Hand-check it on the sample.
10–30Code the optimal-or-better version.
30–35Run samples + your own edge cases: empty, single, duplicates, sorted/reverse, max size.
35–40Fix the obvious bottleneck — or lock in the best partial and Save & Proceed. Partial credit is real; unsubmitted code scores zero.

Pattern recognition — story → pattern

If the problem asks for…Reach for
Longest/shortest subarray or substring under a conditionSliding window + Map/Set
Counts, pairs, subarrays summing to KHash map / prefix sums
Pairs in a sorted array, container-style max/minTwo pointers
Merge, schedule, overlapSort + intervals / greedy sweep
Shortest steps, spread, connected regions on a gridBFS / DFS (multi-source BFS = seed all sources)
Top-K, K closest, streaming extremesHeap / priority queue
Minimum capacity / largest part so a condition holdsBinary search on the answer
Partition a string/array at minimum cost1-D DP

Stories are usually logistics-flavoured (warehouse, delivery, rates, inventory). Strip the story first — the pattern underneath is standard.

Self-prompts (in the test — ask yourself, in order)

"Inputs, output, constraints — stripped of the story? Brute force? What complexity do the constraints demand? Which pattern is this?"
Minute ~20, if stuck: "What simpler version passes most tests? Lock it in, run samples, optimise only with time left."
Final 5: "Tested empty / single / duplicates / max-size? Returning a value, not console.log? Debug prints removed? Numeric sort uses (a, b) => a - b?"

JavaScript traps

  • Array.sort() is lexicographic by default — always pass (a, b) => a - b for numbers.
  • No built-in heap or deque — write a small MinHeap once; BFS with an index-pointer queue, never shift() in a loop on large inputs.
  • console.log goes to Debug Output and doesn't score — return the value, and remove debug prints if the question expects printed output.

Quick solution templates (JavaScript)

Sliding window — longest valid substring/subarray

function longestValid(arr, isOk) {
  let left = 0, best = 0; const seen = new Map();
  for (let right = 0; right < arr.length; right++) {
    seen.set(arr[right], (seen.get(arr[right]) || 0) + 1);
    while (!isOk(seen)) { // shrink until valid again
      seen.set(arr[left], seen.get(arr[left]) - 1); left++;
    }
    best = Math.max(best, right - left + 1);
  }
  return best;
}

Hash map — subarray sum equals K (prefix sums)

function countSubarrays(nums, k) {
  const freq = new Map([[0, 1]]); let sum = 0, count = 0;
  for (const n of nums) {
    sum += n;
    count += freq.get(sum - k) || 0;
    freq.set(sum, (freq.get(sum) || 0) + 1);
  }
  return count;
}

BFS on a grid — shortest steps

function bfs(grid, sr, sc) {
  const R = grid.length, C = grid[0].length;
  const dist = Array.from({length: R}, () => Array(C).fill(-1));
  const q = [[sr, sc]]; dist[sr][sc] = 0;
  for (let head = 0; head < q.length; head++) {
    const [r, c] = q[head];
    for (const [dr, dc] of [[1,0],[-1,0],[0,1],[0,-1]]) {
      const nr = r + dr, nc = c + dc;
      if (nr<0||nc<0||nr>=R||nc>=C) continue;
      if (grid[nr][nc] === 1 || dist[nr][nc] !== -1) continue; // 1 = wall
      dist[nr][nc] = dist[r][c] + 1; q.push([nr, nc]);
    }
  }
  return dist;
}

Binary search on the answer

function minFeasible(lo, hi, feasible) {
  while (lo < hi) {
    const mid = Math.floor((lo + hi) / 2);
    if (feasible(mid)) hi = mid; else lo = mid + 1;
  }
  return lo;
}

Merge intervals

function merge(intervals) {
  intervals.sort((a, b) => a[0] - b[0]);
  const out = [];
  for (const [s, e] of intervals) {
    const last = out[out.length - 1];
    if (last && s <= last[1]) last[1] = Math.max(last[1], e);
    else out.push([s, e]);
  }
  return out;
}

Minimal MinHeap (top-K)

class MinHeap {
  constructor(){ this.h = []; }
  push(x){ const h=this.h; h.push(x); let i=h.length-1;
    while(i>0){ const p=(i-1)>>1; if(h[p]<=h[i]) break; [h[p],h[i]]=[h[i],h[p]]; i=p; } }
  pop(){ const h=this.h, top=h[0], last=h.pop();
    if(h.length){ h[0]=last; let i=0;
      for(;;){ const l=2*i+1, r=l+1; let m=i;
        if(l<h.length&&h[l]<h[m]) m=l; if(r<h.length&&h[r]<h[m]) m=r;
        if(m===i) break; [h[m],h[i]]=[h[i],h[m]]; i=m; } }
    return top; }
  get size(){ return this.h.length; }
}

Q2 — Quick hints

The 60 minutes

TimeDo
0–5Read the README fully — it's the contract. Run Tests before touching code. Failing test names are your map.
5–10If it doesn't build, fix that first. Ask the assistant only for orientation (below).
10–45One failing test at a time: read test → trace route → handler → service → model → smallest fix → Run ALL tests.
45–55Re-read README rules; hunt the unlisted bug — boundaries, empty/missing fields, duplicates, wrong user, error codes.
55–60Final full Run Tests. Confirm the last change saved. Submit. (Time-out evaluates your most recent autosave.)

Pace check: ~10 minutes per bug. At minute 30 with 0–1 tests green, stop deep-diving and triage the cheapest failures first.

Bug checklist — the usual suspects

  • Validation missing → returns 500 instead of 400
  • Existence check missing → no 404
  • Auth/permission check missing → 401/403 handling
  • Mutates but never persists — missing save/update call
  • Wrong route, path, method, status code, or response shape/field name
  • Duplicate check compares the wrong field or type
  • Search/filter: missing filter, case-sensitivity, wrong sort direction
  • Handler sequence to rehearse: route → validate → lookup/404 → auth → mutate → save → correct status & shape (200 / 201 / 400 / 401 / 403 / 404 / 500)

Prompts for the built-in assistant

Ask where / what / why — never "fix it for me." The assistant navigates and explains; it generally won't write the fix, and the transcript may be visible to evaluators. One file, one test, one error at a time.

"Based on the README, which files handle [route/feature]? List the route, handler, and data/model files in order."
"What does the test '[exact test name]' check? What input does it send, and what status and response shape does it expect?"
"Trace a request to [route]: which functions are called, in what order, and where is the data saved?"
"I'm getting this error: [exact error + failing test name]. What does it mean, and which file should I look at first?"
"The endpoint returns 500 instead of 400 for an invalid body. Where is the validation for this route, and what condition does it check?"
"In [function], does the code persist the change after updating it? Walk me through it step by step."
"If I change [function] to check [condition] first, which other tests or routes could that affect?"
"What's the correct syntax in this stack for [generic task]? Show a generic template — I'll adapt it."

Full-solve walkthrough prompts belong in practice sessions on practice repos only — use them after a timed drill to compare a complete fix against yours.

Work Simulation — quick rules

Rate highest the option that: protects the customer · is owned by you · acts promptly · uses the data/materials given · communicates early and in writing.

Rate lowest anything that: hides a problem · blames another team · escalates a decision that's yours · cuts a hidden quality/security corner · waits for perfect information while an issue burns.

  • Deadline slipping? Tell stakeholders early, with impact, options (de-scope, feature-flag, phased rollout), and a revised plan.
  • Disagree? Raise it directly with data, propose an alternative — then disagree and commit.
  • Check the scenario materials (dashboards, logs, wikis) before deciding — Dive Deep beats gut feel.
  • First: check which end of the rating scale is "most effective" — it's easy to read backwards.

Work Style Surveys — quick rules

  • Forced choice, no neutral middle — pick which statement is more like you.
  • Answer as your actual work self on a good day. First instinct, a few seconds per item.
  • The same trait returns reworded — consistency is what's being checked. Don't perform an idealised profile; contradictions are detectable.
  • When two good traits collide, pick the one that's genuinely more characteristic of you.

Sitting-day checklist

  • ☐ Latest Chrome/Edge, extensions disabled, third-party cookies on, stable network (wired if possible), charger in
  • ☐ Single monitor — disconnect others. Quiet room, notifications off, phone away (not a second screen)
  • ☐ Photo ID and webcam ready if prompted
  • ☐ Never use Print Screen (may end the session), outside AI, or outside resources — Q1 is unaided; Q2's built-in assistant is the only exception
  • ☐ Internet drops? The timer keeps running and work is saved — reconnect and log back in if time remains. Never log out — that ends the attempt. Use the in-test "Report a problem" control, and contact the recruiter the same day if it can't be resolved
  • ☐ Done = the confirmation page at the end, after coding + simulation + both surveys
